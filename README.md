# Codex Agent

Pencode 的 Codex 扩展，通过自行启动的 `codex app-server proxy` 连接共享 app-server。proxy 的 stdin/stdout 转发原始 socket 字节，扩展在管道上完成 WebSocket 握手并收发 JSON-RPC；proxy 不转换 JSONL。默认复用已有服务，没有服务时才由 `codex app-server daemon start` 启动共享服务，工作区内各项目和会话共用一个后台连接及 proxy。

- 状态栏底部的 **ChatGPT 图标按钮**（悬停显示 Codex Agent）打开或切回编辑器区域的聊天标签页；通过标签页的关闭按钮关闭后，可再次点击图标打开。
- 聊天标签页分为左右两栏：左侧显示当前聊天记录，输入框固定在聊天记录下方；右侧显示历史会话列表。发送消息或恢复会话后，标签标题跟随当前聊天标题。
- 首次成功发送后，在后台生成简短标题并通过 `thread/name/set` 保存，同步更新标签页和历史列表。标题生成固定使用 `gpt-6-luna` 模型及 `low` 推理强度，沿用 Codex 认证，通过共享服务的独立连接额外进行一次模型请求；临时会话不进入历史，禁用工具并使用只读沙箱，最多等待 60 秒；取消或超时后单独中断标题任务，不影响聊天任务。失败时保留默认标题，后续发送可重试。
- 历史列表每条会话旁的铅笔按钮可修改标题，支持保存和取消；标题不能为空。修改保存到 Codex，恢复会话时保留。手动改名或收到外部标题更新后，待完成的自动标题不会覆盖已有名称。
- 两栏分别滚动；流式回复跟随最新消息，向上翻阅时保留阅读位置，输入焦点、文本选区和历史列表滚动位置在更新时保留。
- 支持流式回复、Markdown、命令输出、文件修改、停止任务和逐次审批。
- 每轮任务结束后，在回复下方显示文件变动卡片，默认收起并显示本轮成功编辑的前 3 个文件、各文件及总计的增删行数；同一路径合并，行数按修改记录累计。收起时保留前 3 个文件，不显示滚动条；展开后的滚动条沿用主题的细滚动条样式。运行中的文件浮层和完成后的列表均只显示完整文件名，长文件名自动换行；点击文件在该行下方展开该轮记录的 diff，再次点击收起，沿用主题高亮。支持“查看变更”在聊天中展开全部 diff。停止或失败时仍展示已成功完成的文件修改，恢复历史会话时重建各轮的变动列表；没有文件修改时不显示卡片。卡片沿用当前主题。
- 每轮发送后，回复上方先显示带扫光的“正在思考”，收到首个回复、计划或思考 token 后移除扫光并切换为“已处理 X分钟 Y秒”，运行中按秒更新。完成、停止或失败后改为固定总耗时“用时 1m 25s”，默认折叠本轮中间消息及工具活动，保留用户消息、最终回复和文件变动卡片；点击用时行展开或收起历史消息，工具详情保留原有展开状态。优先使用 app-server 的 `durationMs`，缺失时使用本地计时；恢复历史时读取服务端保存的耗时，未记录耗时的旧记录不显示估算值。
- 任务进行时，当前会话最新的活动分组在折叠时由摘要文字循环从左到右扫光，展开后由最底部一项的摘要文字扫光，并随新增活动移动，不额外显示处理提示。等待审批或任务结束后停止扫光。Tab 的关闭图标在运行时切换为点阵循环动画，点击后直接关闭界面，任务继续在共享服务中运行，可从历史恢复。关闭按钮、快捷键和右键菜单使用相同流程；停止任务须点击输入框的停止按钮。任务结束后恢复关闭图标。动画沿用主题颜色，不逐帧发送扩展消息或重建布局。
- 聊天记录中，用户消息以右侧气泡展示，Codex 回复平铺显示；连续的思考、命令、读取、搜索和文件修改合并为默认折叠的活动分组。展开分组后显示单条摘要，思考摘要直接显示思考内容的第一行，内容尚未到达时显示“思考摘要”；再点击摘要查看完整思考内容、命令输出或 diff。长列表独立滚动，运行和已拒绝状态在分组折叠时仍可见，展开状态随流式更新保留。活动分组及单条活动不显示失败标识，命令输出和 diff 仍可展开查看。
- 悬停或键盘聚焦用户消息时，在气泡下方显示发送时间和复制按钮，复制保留原消息的 Markdown、换行和空格。会话空闲时还显示编辑按钮，可在消息原位置修改、取消或发送；Enter 发送，Shift+Enter 换行。发送通过 `thread/revert` 回退到该消息所属任务之前，再以修改后的消息重新生成，替换其后的聊天记录，不回退工作区文件。原消息的图片和技能引用随修改后的内容发送，底部输入框的草稿及附件独立保留。回退失败保留原记录，回退成功但发送失败则保留编辑草稿以供重试。此操作需要服务端支持分页历史和 `thread/revert`；未记录时间的旧消息不显示估算时间。
- 输入框采用圆角卡片，两侧保留 8px 间距。左下角 **+** 打开文件选择窗口，可浏览目录或输入路径添加项目外文件；已添加的文件显示在输入框内，点击可移除。文件引用随本次消息发送，发送失败时保留；新会话和各会话的附件草稿独立，远程项目使用工作区服务器上的路径。
- **新会话** 以笔形图标按钮显示在右侧历史栏标题旁，悬停提示“新会话”。右下角的模型按钮向上展开选择菜单，当前模型右侧显示勾选标记；运行时发送按钮切换为停止按钮。
- 新会话、刷新、添加文件、发送和停止等纯图标按钮统一为 24×24px，图标为 14×14px。
- 输入框按 Enter 发送消息，Shift+Enter 换行；输入法选词时按 Enter 不会发送。
- 输入框支持 Ctrl+V（macOS 为 Cmd+V）粘贴剪贴板图片，显示沿用当前主题的缩略图，点击可移除。可连续粘贴多张图片，随文本一起发送，也可仅发送图片；发送原图，单张需小于约 1.5 MiB，超出时提示错误。图片随项目及会话草稿独立保存，发送失败时保留，成功后清空；消息记录显示图片缩略图。
- 在消息开头输入 `/` 列出当前项目可用且已启用的 skill，按名称、显示名称或描述筛选。列表通过 `skills/list` 获取并缓存，收到 `skills/changed` 后重新加载。选择后在光标处直接插入 skill 的 Markdown 链接，发送时原样保留该链接正文。加载失败时显示错误，关闭后重新输入 `/` 可重试。
- 输入 `@` 弹出项目文件和文件夹候选，按名称或相对路径筛选。选择后在光标处插入 `[名称](路径)`，链接标题不带 `@`；`/` 选择技能时标题也不带 `$`。输入框将引用显示为主题色链接名称，光标紧跟链接和补全空格；左右方向键整段越过引用，退格和 Delete 整段删除引用及其补全空格。发送、复制和撤销保留完整 Markdown。菜单支持鼠标选择、↑/↓ 切换、Enter/Tab 确认和 Esc 关闭，沿用当前主题。文件索引在首次引用时建立，后续筛选复用缓存；重新打开候选时最多每 30 秒刷新一次。跳过版本控制、依赖和构建目录，不跟随符号链接；最多索引 20,000 个文件和文件夹、遍历 40,000 个条目。切换项目或关闭标签页会释放索引。
- 模型菜单通过 `model/list` 读取真实可用模型，每次连接缓存一次；选中模型后继续选择该模型支持的推理强度，按钮在模型名称右侧同一行显示强度。菜单支持方向键导航、Esc 和点击外部关闭；加载失败可重试。返回模型列表或中途关闭不会修改原选择。
- 输入框左下角的权限按钮向上展开三档菜单：**请批准**、**帮我批准**、**完全访问权限**，当前选项右侧显示勾选。完全访问使用橙色提示；**了解更多** 展开权限说明。
- 模型、推理强度和权限按项目保存在 `.pencode/codex.json`，选择完成后立即保存，重启扩展或切换项目、会话标签页时恢复。新项目默认使用 Codex 配置的模型和 **请批准** 权限；从下一次发送开始应用于新建、恢复和已有会话，不影响正在执行的任务。权限与模型菜单互斥，隐藏或关闭聊天标签页会关闭菜单。
- **新会话** 在当前 Codex 标签页内切换到新会话，保留先前会话的聊天记录、输入草稿、附件和运行中的任务；右侧历史列表可继续已有会话，各会话保留输入草稿。历史列表的 **刷新** 重新读取当前项目的会话，**更多会话** 加载下一页。
- 历史按当前项目目录筛选，切换 IDE 活动项目时自动读取对应项目的会话，项目草稿独立保留。列表包含 CLI、VS Code 和 app-server 创建的会话，分页和刷新按会话 ID 去重，支持加载更早的消息记录。列表查询使用 `useStateDbOnly: true`，直接读取 Codex 状态数据库，避免启动、刷新和翻页时扫描历史 JSONL 文件导致超时；未进入数据库索引的旧记录需由 Codex 完成索引后才会出现。
- 切换历史会话、切换项目或关闭 Codex 标签页时，保留运行中会话的连接、流式进度和审批请求，任务继续在后台执行；再次打开标签页恢复先前选中的会话。历史列表显示运行中的旋转指示；后台任务成功完成后改为主题绿色圆点，查看对应会话后清除。切换到其他编辑器标签时，Codex 标签页同样显示运行或未读完成状态。
- 扩展通过 `Handlers.Lifecycle` 监听主窗口和项目关闭请求，包括关闭 Codex 标签页后的后台会话。仍有任务运行时，宿主先要求确认，再处理未保存文件；取消关闭保留全部会话。项目实际关闭后释放该项目的扩展状态；退出主程序时断开扩展连接，共享 daemon 继续独立管理其任务。
- 连接同一共享服务的客户端可恢复同一个会话，同步接收流式事件和审批结果；通过 `thread.status` 和 `thread/status/changed` 同步运行状态。一个客户端关闭界面后，其他客户端仍可继续。已有任务运行时不能另开独立并行任务，需等待或明确停止。
- 会话被独立 app-server 持有时，通过 `thread/read` 读取元数据，并持续使用 `thread/turns/list` 同步已保存的消息、命令输出和文件修改。查看或运行中每秒同步，后台空闲时每五秒检查；内容未改变时不重建聊天项，更新时保留草稿、展开状态和更早历史。关闭标签后继续同步，后台成功完成显示绿色未读点。原客户端仍管理任务和审批，观察界面不提供停止操作；发送时重试恢复会话，失败保留草稿和附件。
- 独立服务不提供跨服务的流式订阅：同步受原服务保存记录的时机影响，尚未保存的 token 和审批请求无法同步。CLI 0.166.0 的历史接口会把未结束轮次标为 `interrupted`；扩展仅对最新、已开始且没有结束时间、耗时或错误的轮次推断为运行中。正常完成和停止会保存结束时间；进程崩溃留下的未结束记录无法靠此接口准确判断。需要完整实时状态及审批协作时，应连接同一个共享服务。

## 构建与运行

需要 Go 1.27+，以及工作区服务器上支持 `app-server proxy` 和 `app-server daemon start` 的 Codex CLI（已验证 0.166.0）。默认和 Unix socket 连接均需要 CLI；显式 WebSocket 地址可直接连接已启动的共享 app-server。先在服务器运行 `codex login`。不单独存储 API Key 或登录信息。

从 Pencode 仓库根目录执行：

```sh
make install-extensions
make run
```

安装命令会自动发现本目录，构建扩展并为 Windows 添加 `.exe` 后缀。

本扩展是独立仓库，在 Pencode 中通过 `extensions/codex` Git 子模块引用。已有主项目可运行 `git submodule update --init extensions/codex` 初始化。

单独克隆、开发和测试，无需检出 Pencode 主项目或 Onix：

```sh
git clone git@github.com:pencode-labs/codex.git
cd codex
go test ./...
go build -o bin/codex-agent .
```

`go.mod` 固定 Pencode `peb` SDK 的版本，由 Go 下载依赖，不使用指向主项目的本地 `replace`。测试通过内置的 app-server 子进程模拟运行，默认无需安装 Codex CLI、登录或网络模型请求。

Windows 单独构建时使用 `go build -o bin/codex-agent.exe .`。如需从扩展管理器选择本目录安装，将 `resources/extension.json` 的 `entry` 改为 `bin/codex-agent.exe`。本扩展依赖 `peb.EditorTab` 及编辑器内分栏和滚动支持，需要同时更新 Pencode 主程序。

在 IDE **设置 → Codex Agent → Codex 可执行文件路径** 中指定原生 Codex 可执行文件或其所在目录；填写目录时使用其中的 `codex.exe`（Windows）或 `codex`（macOS/Linux），目录中没有该程序时提示具体错误。支持 Windows 路径（如 `C:\Program Files\Codex\codex.exe` 或 `C:/Tools/codex.exe`）、macOS/Linux 路径（如 `/usr/local/bin/codex`）、用户目录（如 `~/.local/bin/codex`，Windows 也支持 `~\bin\codex.exe`）以及相对于项目目录的路径（如 `./tools/codex`）。路径包含空格时无需添加引号；只填写命令名时从 `PATH` 查找。

此设置优先于环境变量 `PENCODE_CODEX_PATH`；留空时先使用该环境变量，再从 `PATH` 查找 `codex`。macOS 从 Finder 或 Dock 启动时，如果 GUI 进程没有继承 `.zprofile` / `.zshrc` 中的路径，扩展会再通过登录交互式 shell 读取 `PATH`，并用得到的环境启动 Codex proxy 和 daemon。仍然找不到时，可直接填写 `command -v codex` 返回的绝对路径。修改在下次连接时生效，可通过切换会话或重启扩展建立新连接；这些操作只断开当前连接，聊天任务继续运行。可执行文件不经过 shell，不接受命令字符串。远程工作区使用服务器的路径格式，进程、认证和文件操作均在服务器运行。

在 IDE **设置 → Codex Agent → Codex 共享服务地址** 中留空时，扩展先探测 `$CODEX_HOME/app-server-control/app-server-control.sock`（未设置 `CODEX_HOME` 时使用 `~/.codex`），支持 Codex 为较长路径创建的 socket 符号链接。已有服务时，扩展启动自己的 `codex app-server proxy --sock <路径>` 接入；其他客户端使用 `codex app-server --listen unix://` 启动的服务同样可以复用。只有 socket 不存在或连接被拒绝时，才调用 `codex app-server daemon start`，由 CLI 的单例管理处理并发启动，再启动 proxy 连接返回的 socket。认证、权限、握手失败和连接超时会直接报告，不会另起服务。重连及自动标题使用各自的 proxy 连接同一个共享服务，标题 proxy 在任务结束后回收。

关闭标签页时保留后台连接和 proxy，以继续接收运行状态；连接释放或退出扩展时，会关闭管道并终止、回收扩展自己启动的 proxy，不会停止共享服务。其他程序持有自己的 proxy 或连接。相同用户及 `CODEX_HOME` 共用一个服务，daemon 在客户端退出后继续运行属于其设计；需要停止时由服务管理方执行 `codex app-server daemon stop`。扩展不按 PID 查找或终止共享服务，也不扫描其他用户的服务。

也可以自行启动服务，无需使用 daemon 子命令：

```sh
codex app-server --listen ws://127.0.0.1:4500
```

将共享服务地址设置为 `ws://127.0.0.1:4500`，所有客户端连接此地址。地址还支持 `wss://...`、`unix://`（默认 socket）和 `unix:///绝对路径/control.sock`。Unix 地址通过扩展自行启动的 proxy 接入；`unix://` 由 CLI 选择默认 socket，自定义路径通过 `proxy --sock` 传入。Windows 可使用显式 WebSocket 地址。WebSocket 地址直接连接，不执行 Codex CLI。指定地址时均不自动启动服务，服务需由启动方保持运行。只有通过 socket 或 WebSocket 监听的服务可以接入；独立 stdio 服务的进程不提供供其他客户端共享的监听地址。

服务地址设置优先于环境变量 `PENCODE_CODEX_SERVER_URL`，两者均为空时自动发现默认服务。启用 WebSocket bearer 认证的服务可通过扩展进程环境变量 `PENCODE_CODEX_SERVER_TOKEN` 提供令牌。远程工作区由工作区服务器建立连接。CLI 或桌面客户端也必须连接同一个后端才能共享正在运行的会话；仅使用同一个 `CODEX_HOME` 无法共享独立进程的写锁。

项目设置保存在工作区服务器的项目根目录下，例如 `.pencode/codex.json`：

```json
{
  "model": "",
  "permission": "ask"
}
```

`model` 为空表示使用 Codex 默认模型；可选的 `reasoningEffort` 保存推理强度，取值来自模型目录（例如 `low`、`medium`、`high`）。选择“默认”同时清除模型和强度覆盖；未声明强度选项的模型直接完成选择。`permission` 可为 `ask`（请批准）、`auto`（帮我批准）或 `full`（完全访问权限）。配置读取失败时使用默认值并提示错误；保存失败时保留原选择并提示错误。打开项目不会创建配置文件，首次完成模型或权限选择时才写入。

选择“默认”时使用 Codex 配置；选择具体模型时传给 `thread/start` 和 `turn/start`，推理强度通过每次 `turn/start` 的 `effort` 字段传入。未选择强度时使用已加载模型目录的默认强度。权限在 `thread/start`、`thread/resume` 和每次 `turn/start` 显式传入，需要支持 `approvalsReviewer` 的 Codex CLI：

| 权限 | 沙箱 | 审批策略 | 审批者 |
| --- | --- | --- | --- |
| 请批准 | `workspace-write` | `on-request` | `user` |
| 帮我批准 | `workspace-write` | `on-request` | `auto_review` |
| 完全访问权限 | `danger-full-access` | `never` | `user` |

前两档的任务使用禁止网络访问的工作区沙箱，外部文件和网络访问需经过审批。自动审查由 Codex app-server 执行，可能拒绝风险操作并产生额外用量。完全访问允许直接执行操作。远程项目的权限作用于工作区服务器。交互审批请求在对应会话内展示，支持 `item/tool/requestUserInput` 的文本回答。未实现的服务端请求返回明确的 JSON-RPC 错误，不会默默挂起。

## Output 日志

在 IDE 的 **Output → Extension: codex** 中查看扩展日志。带 `[Codex]` 前缀的日志包含时间、连接标识、工作目录、服务地址及其来源，记录默认 socket 探测、共享 daemon 的启动或复用、实际可执行文件及完整参数、proxy PID 和回收结果、WebSocket 握手和错误。Codex 子进程的 stderr 也会实时进入同一通道。

RPC 仅在出错时记录日志，不记录常规请求、响应、通知或流式 token，也不输出请求或响应正文；服务地址日志省略用户信息、查询参数和片段，bearer 认证仅记录是否启用。

## 验证

```sh
go test ./...
go test -race ./...
```

主项目保留原生渲染回归测试，使用自身的测试资源快照。跨仓库端到端测试需在 Pencode 根目录显式运行 `go test -p 1 -tags codex_integration ./workbench`，并先初始化 Codex 子模块；扩展自身的测试不依赖这些工作台测试。

无网络的协议测试通过原始字节 proxy 子进程和本地 WebSocket 服务模拟 app-server，覆盖管道上的 WebSocket 握手、流式事件、审批、明确停止、双 proxy 共享、关闭后继续及重连，以及启动和历史读取阻塞时关闭、重开标签页。服务发现及进程测试覆盖 socket 符号链接、已有服务复用、失效 socket 启动一次后复用、认证拒绝时不启动 daemon，以及各客户端独立持有和回收 proxy。同步测试覆盖后台自动轮询、更新已有消息和输出、文件统计去重、展开状态保留、多页追赶及未读状态。可选真实 CLI 测试使用隔离的 `CODEX_HOME` 和受控前台 app-server，清理时先取消进程并等待退出，再删除目录；不安装 daemon，避免留下其独立更新辅助进程。测试验证自动发现、多客户端恢复同一持久会话，并通过本地模拟模型服务验证关闭界面后继续、明确停止，以及两个独立 app-server 进程之间的运行内容、成功和停止状态同步，不向 OpenAI 发起推理请求：设置 `PENCODE_CODEX_INTEGRATION=1` 后运行 `go test -run TestLive -v`。

消息与命令输出按条保留最多 128 KiB 的显示文本，标签页展示最近约 1.2 MiB 的 HTML。完整会话仍由 Codex 持久化。当前未实现图片附件、MCP 表单或账户登录界面；登录请使用 CLI。扩展视图不会加载模型输出中的图片资源。

协议依据：[OpenAI Codex app-server 文档](https://developers.openai.com/codex/app-server)。

## 发布

推送 `v*` 标签（如 `v0.1.0`）或发布 GitHub Release 后，工作流会先测试，再构建
Linux、macOS、Windows 的 amd64/arm64 扩展包，并上传 ZIP 和 `SHA256SUMS` 到对应 Release。
推送标签时若尚无 Release，会自动创建；预发布标签（如 `v0.1.0-rc.1`）会创建预发布版本。

压缩包内含 `bin/`、`resources/`、README 和许可证，清单版本取自标签，Windows 入口自动添加 `.exe`。
选择与工作区服务器匹配的平台和架构，解压后在扩展管理器中选择该目录安装。
